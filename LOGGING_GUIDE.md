# Получение логов из приложения на реальном устройстве

## Способ 1: Console.app на Mac (Рекомендуется)

### Шаги:

1. **Подключите устройство к Mac через USB**

2. **Откройте Console.app** (Программы > Утилиты > Консоль)

3. **Выберите ваше устройство** в левой панели

4. **Настройте фильтры для просмотра логов:**

   В поле поиска вверху справа введите один из фильтров:

   - **Для логов таймера:**
     ```
     category:Timer
     ```

   - **Для логов агитации:**
     ```
     category:Agitation
     ```

   - **Для всех логов приложения:**
     ```
     subsystem:YOUR_BUNDLE_ID
     ```
     (замените YOUR_BUNDLE_ID на Bundle Identifier вашего приложения)

5. **Запустите приложение на устройстве** и воспроизведите проблему

6. **Наблюдайте логи в реальном времени**

### Экспорт логов:

1. Выделите нужные логи
2. Меню: File > Export Selected Items...
3. Сохраните в файл для дальнейшего анализа

## Способ 2: Через Xcode

### Шаги:

1. **Подключите устройство к Mac**

2. **Откройте Xcode**

3. **Меню: Window > Devices and Simulators**

4. **Выберите ваше устройство**

5. **Нажмите кнопку "View Device Logs"**

6. **Запустите приложение и воспроизведите проблему**

7. **Логи будут видны в окне**

## Способ 3: Для TestFlight сборок без подключения к Mac

### Используйте профиль логирования:

1. **На устройстве откройте Settings > Privacy & Security > Analytics & Improvements**

2. **Включите "Share iPhone Analytics"**

3. **После воспроизведения проблемы:**
   - Settings > Privacy & Security > Analytics & Improvements > Analytics Data
   - Найдите файлы с именем вашего приложения
   - Отправьте их себе через Share

## Ключевые категории логов в приложении:

### Timer (Таймер)
Логи основных операций таймера:
- Инициализация ViewModel
- Запуск/пауза/сброс таймера
- Тики таймера (первые 5 и каждый 10-й)
- Время создания Timer объекта
- Задержки выполнения

### Agitation (Агитация)
Логи системы агитации:
- Выбор режима агитации
- Настройка фаз агитации
- Переключение между фазами
- Параметры агитации

### Persistence (Хранение данных)
Логи работы с базой данных SwiftData:
- Инициализация SwiftData
- Валидация схемы
- Стратегии восстановления при ошибках
- Создание/удаление сущностей
- Проблемы с миграцией данных

### Sync (Синхронизация)
Логи синхронизации данных:
- Автоматическая синхронизация при запуске
- Синхронизация с GitHub
- Обновление режимов агитации
- Статус подключения к интернету
- Ошибки синхронизации

### Navigation (Навигация)
Логи навигации по приложению:
- Переходы между экранами
- Загрузка записей журнала
- Открытие деталей

### UI (Пользовательский интерфейс)
Логи интерфейса:
- Отображение подсказок (coach marks)
- Действия пользователя
- Состояние UI компонентов

## Что искать при отладке проблем с запуском таймера:

1. **Задержка между нажатием кнопки и первым тиком:**
   ```
   startPauseTimer called
   startTimer BEGIN
   Timer object created
   Tick #1
   ```
   Проверьте временные метки между этими событиями

2. **Проблемы с созданием Timer:**
   ```
   Timer object created (creation took X.XXXs)
   ```
   Если X > 0.1s, это может указывать на проблему

3. **Медленное выполнение updateTimer:**
   ```
   WARNING: updateTimer took X.XXXs
   ```
   Указывает на задержки в обработке тиков

4. **Проблемы с агитацией:**
   Проверьте логи setupAgitation на корректность параметров

## Примеры команд фильтрации в Console.app:

### Показать только ошибки таймера:
```
category:Timer type:error
```

### Показать все логи синхронизации:
```
category:Sync
```

### Показать проблемы с базой данных:
```
category:Persistence type:error
```

### Показать логи за последние 5 минут:
```
category:Timer AND timestamp >= -5m
```

### Найти конкретное сообщение:
```
category:Timer AND message CONTAINS "startTimer"
```

### Показать все категории приложения:
```
subsystem:YOUR_BUNDLE_ID
```

### Комбинированный фильтр (ошибки во всех категориях):
```
subsystem:YOUR_BUNDLE_ID AND type:error
```

## Удаление логирования для production:

Если нужно отключить избыточное логирование в финальной версии, в файле `Logger.swift`:

1. Установите более высокий порог логирования
2. Или оберните детальные логи в `#if DEBUG`

Текущая реализация уже использует OSLog, который автоматически управляет производительностью и хранением логов.
